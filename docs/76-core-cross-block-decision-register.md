- **VERIFIED ON MAIN** — exact existing runtime path/test supports the narrow claim.

- **ABSENT / BLOCKED** — no supported in-repository implementation/decision was found.
- **OWNER DECISION** — the named owner must select/approve a policy before implementation is justified.

## Cross-block consistency findings

1. **Do not confuse a runtime primitive with an end-to-end contract.** The authorized-read service, snapshot cursor, admin Relationship writer and deterministic projection rebuild exist, but do not combine into a production Memory→NPC consumer.
2. **Do not use `commit_sequence` alone for invalidation.** Rollback can change `world_revision` while the sequence is unchanged. Neither cursor is a per-source version or durable journal.
3. **Do not conflate provenance layers.** A summary producer is not necessarily the author/source of its claims; manifest membership is not authorization; context inclusion is not delivery; delivery is not receipt; receipt is not belief.
4. **Keep World Pack version and rule-module version distinct.** Existing committed typed effects pin `rule_module_id + rule_module_version`; the target World Pack match is validated through the registered manifest. Do not claim the event independently stores a World Pack version unless a test proves it.
5. **Keep semantic replay separate from migration.** Rebuilding a projection from surviving committed effects is not historical re-evaluation under a missing module, and neither implies an approved meaning-changing migration.
6. **PR scope hygiene is required before review.** At the time of the initial audit, PR #138 and PR #139 crossed the assigned NPC-only scope by including Personality-owned files. Follow-up isolation PRs #150 (NPC lineage tests) and #151 (NPC Memory-boundary matrix) now exist as separate NPC-owned changes. Review those isolated PRs on their exact heads; the original mixed-scope PRs #138/#139 must not be treated as NPC-only evidence unless their diffs are cleaned up or explicitly split by the owners.
