# World Simulation Engine — «Логический движок»

**«Логический движок» — проект универсального движка длительной ролевой симуляции.** Цель — хранить авторитетное состояние мира, рассчитывать причинно связанные изменения и процессы игрового времени, поддерживать автономность NPC и передавать подтверждённые результаты в повествование через адаптер SillyTavern.

> **Фактический статус на 24 октября 2026 года:** архитектурные контракты и минимальный исполняемый прототип. В runtime уже есть HTTP API, SQLite-журнал событий, базовые сущности и факты, идемпотентность, аудит, ограниченный причинный откат, версионируемый реестр механик и базовый жизненный цикл предложений. Полноценная автономность NPC, долговременные процессы, система приобретения знаний и убеждений, типизированные отношения персонажей, actor-authorized фильтрация состояния, World Pack loader и проверенный адаптер SillyTavern **ещё не реализованы**. Открытые PR и проектные документы не считаются реализованными возможностями до проверки кода и тестов; открытые PR не означают, что изменения уже слиты в `main`.

## Основной принцип

**Замысел ≠ происходящее ≠ рассказанное.**

1. Сюжетные арки описывают предполагаемые цели, опорные точки и допустимые варианты.
2. Симуляция вычисляет, что фактически произошло, на основании состояния, правил мира, действий, знаний и причин.
3. Повествование отражает подтверждённые результаты и не создаёт канонические факты само по себе.

## Непереговорные требования

- Игровое время заморожено, пока игрок не совершает действие и не запрашивает продвижение времени.
- Движок — источник авторитетного состояния; языковая модель предлагает действия и формулирует повествование, но её предложения валидируются.
- NPC должны действовать автономно на основании характера, целей, ресурсов, отношений и доступных им знаний. Секреты не распространяются между персонажами без источника. Это целевое требование, а не заявление о завершённой реализации.
- Поддерживаются как заданные сюжетные арки, так и свободная симуляция.
- Сохранённые задачи, планы и длительные процессы должны продолжаться независимо от того, помнит ли о них текущий контекст модели.
- Откат сообщения должен устранять зависимые от него последствия, включая знания, процессы и сюжетные условия; независимые ветви должны сохраняться. Полная поддержка альтернативных независимых причин пока не подтверждена.
- Векторный архив — источник поиска контекста, а не авторитетная база фактов. Существующий патч векторизации не переписывать.
- SillyTavern на Android/Termux остаётся целевым RP-интерфейсом; движок работает на компьютере. Конкретные хуки интеграции необходимо проверить, а не предполагать.
- Общее ядро не навязывает миру чужие механики. Специфические правила принадлежат отдельному World Pack; неизвестные механики явно маркируются.

## Текущая граница реализации

| Область | Статус |
|---|---|
| Канонические события, SQLite-проекции, базовый аудит и идемпотентность | Реализовано в прототипе; проверять по текущим тестам |
| Причинный откат и перестроение проекций | Частично реализовано; общая поддержка альтернативных источников не реализована |
| Перевод предложений механик в канонические эффекты | Изменения находятся в открытой цепочке PR; не считать слитыми |
| Стабильная идентичность `fact.set` | Изменения находятся в открытом PR #43; не считать слитыми |
| Согласованный внутренний снимок чтения | Открытый PR #45; не слит и не предоставляет авторизацию |
| Типизированные отношения персонажей | Контракт проектируется; runtime-операции нет |
| Доверенное различение начальных данных, авторских исправлений и внутриигровых изменений | Полная граница авторизации ещё не реализована |
| Чтение знаний с учётом персонажа, цели, видимости и секретов | Не реализовано |
| Автономные NPC, долговременные процессы, StoryBeat, World Pack loader, адаптер SillyTavern | Не реализовано |

**Важно:** согласованный снимок данных не является разрешением на доступ. Сырые сущности, факты и метаданные событий из внутреннего snapshot нельзя напрямую передавать NPC, повествователю или игроку. Аналогично, запись о причинной зависимости не означает, что система поддерживает логическое «ИЛИ» между независимыми источниками.

### Исполняемый прототип
- `package.json` — Node.js runtime scripts.
- `src/core/` — ошибки и ограниченный декларативный evaluator.
- `src/application/engine.js` — прикладные команды и проверка входных данных.
- `src/storage/sqlite-store.js` — журнал событий, проекции состояния, аудит и прототип причинного отката.
- `src/api/server.js` — независимый от интерфейса HTTP API.
- `tests/` — начальные контрактные тесты.
- `docs/20-minimal-runtime.md` — запуск, endpoints и ограничения текущей реализации.

Запуск требует Node.js 22.13+ и `ENGINE_API_TOKEN` (не менее 16 символов). Для создания proposals настрой `ENGINE_ADAPTER_TOKENS` как JSON-объект идентификаторов адаптеров и отдельных секретов; для регистрации механик/модулей задай отдельный `ENGINE_ADMIN_TOKEN`. `ENGINE_APPROVAL_TOKEN` включает отдельный gate подтверждения. Пример переменных находится в `.env.example`. `npm test` запускает текущие тесты. Встроенный `node:sqlite` в используемых версиях Node может помечаться как experimental.

## Статус и порядок работы

Архитектурные контракты развиваются вместе с минимальным runtime-каркасом. Прототип пока не равен полноценному движку и не должен использоваться как production-система: причинные ссылки задаются вызывающей стороной и не проверяются на полноту; нет завершённой модели знаний, автономных процессов и проверенного SillyTavern-адаптера. Возможности считаются реализованными только после проверки соответствующего кода и тестов на актуальном коммите.

Текущая экспериментальная реализация использует JavaScript/Node.js + SQLite. Архитектура API не привязана к SillyTavern; конкретные хуки ST-адаптера необходимо проверить отдельно.
